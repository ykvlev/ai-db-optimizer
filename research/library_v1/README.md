# Дополнительный корпус «Библиотека»

Статус: подготовлен к предварительной проверке; модельных ответов нет.
Это вручную составленный синтетический корпус, не независимая выборка рабочих SQL.

## Состав

- 12 исходных запросов в одной дополнительной предметной области.
- 28 состояний: фиксированное, семь граничных профилей и 20 псевдослучайных
  состояний с заранее заданными начальными значениями генератора.
- 4 положительных контроля с обоснованиями.
- Ожидаемые значения вычислены отдельной реализацией намерения на Python.
- Первичные и внешние ключи, уникальность имён, обязательность полей;
  NULL допустим только в `returned`. Сбор может быть отрицательным
  (корректировка/возврат); неотрицательность схемой не предполагается.

Порядок каждого результата детерминирован. В `UNION ALL` одинаковые строки
неразличимы, но их кратности сохраняются. Текстовые сравнения и сортировки
не используются: различия правил сравнения строк СУБД не маскируются.

## До генерации моделей

1. `prepare.py` создаёт `corpus.json` и отказывается перезаписывать файл.
2. В CI после сборки `preflight.py` исполняет эталоны и контроли в новых
   схемах MySQL и PostgreSQL с реальными ограничениями целостности.
3. Проверяется 672 исполнения эталонов и 224 исполнения положительных
   контролей. Они не являются ответами моделей или независимыми запросами.
4. Сохранить SHA256 корпуса, отчёт CI, commit и digest опубликованного образа.
   Только после успешного этапа считать корпус зафиксированным.
5. После получения ответов не менять корпус; изменения требуют новой версии.

Два драйвера могут описывать типы по-разному. Интерфейсы контролей сравниваются
с эталоном внутри каждой СУБД; между СУБД сравниваются ожидаемые значения.

## Следующий этап

Основная генерация планируется для MySQL: Qwen2.5-Coder 7B и Phi-3.5 Mini,
по одному ответу на каждый из 12 запросов. Это 24 генерации. Исполнение
эталонов на PostgreSQL не подтверждает переносимость модельных кандидатов.
Параметры и ограничения остаются из `docs/RESEARCH_NEXT_PROTOCOL.md`.
Переход к сбору требует успешного CI и готового локального исследовательского
запуска; приложение и его CD не считаются автоматически конвейером исследования.

Профили не построены по будущим ответам моделей. Общие конструкции пересекаются
с прошлыми сериями; независимость семантических задач не заявляется.
