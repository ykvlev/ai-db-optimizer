# SQL Optimization Dataset v1.0.0

База данных результатов интеллектуальной оптимизации SQL-запросов, полученная в экспериментах
программного комплекса [AI Database Optimizer](https://github.com/ykvlev/ai-db-optimizer).

Автор и правообладатель: Яковлев Артём, Политехнический колледж НовГУ, 2026.
Лицензия: [CC BY 4.0](LICENSE) — свободное использование с указанием авторства.

## Что внутри

Каждая запись — одна пара «SQL-запрос × участник» в одном эксперименте. Участник — языковая модель
(`ollama:qwen2.5-coder:7b`, в том числе вариант без плана выполнения в контексте) или детерминированный
переписыватель `baseline:rule-based`. Для каждой пары сохранены исходный запрос, предложенный кандидат, планы
выполнения до и после, пять замеров времени каждого запроса, результат проверки эквивалентности, исход и,
для модели, полный промпт и ответ.

Все показатели измерены на реальных СУБД, ничего не сгенерировано и не оценено «на глаз».

| Показатель | Значение |
|---|---|
| Записей | 304 (из них 128 — ответы языковой модели) |
| Экспериментов | 6 |
| Уникальных запросов | 96 (shop-bench-v1: 40 для MySQL и 40 для PostgreSQL; shop-bench-mini-v1: 16 для MySQL) |
| Категорий запросов | 16, включая контрольную группу уже оптимальных запросов |
| СУБД | MySQL 8.4.11, PostgreSQL 16.15 |
| Исходы | улучшено 59, без изменений 225, ухудшено 17, некорректно 3 |

## Файлы

| Файл | Содержимое |
|---|---|
| `records.jsonl` | полные записи (одна JSON-строка на запись) |
| `records.csv` | те же записи в плоском виде для Excel/pandas (UTF-8 с BOM) |
| `llm_io.jsonl` | системный и пользовательский промпты, сырой ответ модели (по `record_id`) |
| `queries.csv` | тексты запросов наборов shop-bench-v1 и shop-bench-mini-v1 с категориями |
| `experiments.json` | параметры экспериментов: версии СУБД, программы, промпта, модели, бенчмарка |
| `schema/*.sql` | схема и детерминированный генератор данных испытательной БД (seed `shop-seed-v1`) |
| `prompts/*.json` | версии промптов; контрольная сумма SHA-256 указана в каждой записи |
| `stats.json` | сводные счётчики |
| `SHA256SUMS` | контрольные суммы всех файлов |

## Поля записи (`records.jsonl`)

| Поле | Описание |
|---|---|
| `record_id` | идентификатор `e<эксперимент>-<запрос>-<участник>` |
| `experiment_id`, `dbms`, `dbms_version` | эксперимент и СУБД |
| `query_set`, `database_seed` | версия набора запросов и данных |
| `query_key`, `category`, `title` | запрос и его категория |
| `participant`, `participant_type` | участник: `llm` или `rule_based` |
| `prompt_version`, `prompt_sha256` | версия промпта и контрольная сумма его файла |
| `original_sql`, `candidate_sql` | исходный запрос и предложенный вариант (`null` — изменений не предложено) |
| `proposed`, `executed` | кандидат отличается от исходного; кандидат выполнился без ошибок |
| `outcome` | `improved` (ускорение ≥ 1,05), `unchanged`, `worse` (< 0,95), `invalid`, `error` |
| `verdict`, `verdict_reason` | решение системы проверки и его причина |
| `error_types` | `RESULT_CHANGED`, `PERFORMANCE_REGRESSION`, `INVALID_RESPONSE`, `WRONG_COLUMN` и др. |
| `detected_issues` | коды проблем, найденных детерминированным анализатором (17 правил) |
| `equivalence` | статус, число строк и контрольные суммы результатов обоих запросов |
| `speedup`, `time_before_ms`, `time_after_ms` | медиана времени и ускорение |
| `benchmark_original`, `benchmark_candidate` | все замеры (`times_ms`), прогрев, статистика, прочитанные строки |
| `plan_original`, `plan_candidate`, `plan_changes` | деревья планов выполнения и перечень изменений |
| `llm_*` | пояснение, самооценка уверенности и рекомендованные индексы модели |
| `latency_ms`, `prompt_tokens`, `completion_tokens` | время ответа модели и объём в токенах |

## Методика

- Эквивалентность: оба запроса выполняются на одной БД, для каждой строки результата считается SHA-256
  канонического представления, контрольная сумма набора строк — сумма хешей по модулю 2^128 (не зависит от
  порядка, учитывает повторы); при `ORDER BY` дополнительно сравнивается порядок.
- Время: 2 прогревочных запуска, затем 5 замеров с чередованием исходного и нового запроса; метрика — медиана.
- Подключение только на чтение (транзакция `READ ONLY`, пользователь с правом `SELECT`).
- Стенд: Intel Core i5-13420H, 16 ГБ ОЗУ, без GPU, Windows 11, СУБД в Docker; модель Qwen2.5-Coder-7B (Q4_K_M)
  через Ollama на CPU, температура 0,1, контекст 4096 токенов.

Испытательная БД воспроизводится запуском `docker compose up` в репозитории программы.

## Ограничения

Одна небольшая модель; каждый запрос обработан моделью однократно; данные испытательной БД синтетические;
проверка эквивалентности эмпирическая; исходы вблизи порогов 0,95 и 1,05 чувствительны к шуму измерений.
