# CI/CD оптимизатора

Последовательность: push → build → test → package → registry → staging → production.

## CI

`.github/workflows/ci.yml` запускается после push и для pull request. Этапы выполняются последовательно: сборка интерфейса, backend-тесты с настоящими MySQL/PostgreSQL, упаковка Docker-образа и проверка API/интерфейса, публикация того же образа в GitHub Container Registry. Для pull request публикация отключена. Пропущенные интеграционные тесты считаются ошибкой конвейера.

Образ маркируется полным SHA коммита. Артефакт `release-image` хранит ссылку с digest; CD использует её вместо изменяемого `latest`. Для начального внедрения нужно опубликовать эти файлы в репозитории и получить успешный CI. Локальные проверки сами по себе не являются завершённым CI/CD.

## CD на компьютере пользователя

В репозитории нужен Windows x64 runner с дополнительной меткой `science-deploy`, PowerShell 7 и Docker Desktop в режиме Linux containers. Запускать runner от пользователя, у которого доступен Docker Desktop. Конвейер `CD local` запускается вручную на основной ветке с номером успешного CI-запуска этой ветки. Проверка источника выполняется на GitHub перед передачей задания локальному runner.

В GitHub создать environments `staging` и `production`; ограничить развёртывание основной веткой. При наличии доступного для репозитория обязательного ревью назначить пользователя reviewer для production.

| Окружение | Интерфейс | MySQL | PostgreSQL | Compose project |
|---|---|---|---|---|
| staging | http://localhost:8081 | 3308 | 5435 | science-staging |
| production | http://localhost:8082 | 3309 | 5436 | science-production |

Окружения имеют отдельные тома истории и отдельные демонстрационные базы shop. Порты привязаны к 127.0.0.1. Подключения к демонстрационным базам добавляются через интерфейс: host `localhost`, порт из таблицы, база `shop`, пользователь/пароль `optimizer_ro`. Облачные ключи моделей не входят в образ. Каждое окружение получает собственный случайный административный пароль СУБД в `%LOCALAPPDATA%\ScienceDeploy`; не публиковать содержимое этой папки.

При выборе production сначала разворачивается и проверяется staging. Затем production получает тот же digest. После успешной проверки API и интерфейса сохраняется квитанция версии. При сбое обновления восстанавливается предыдущий образ приложения; тома не удаляются. Это откат версии приложения, не откат данных или миграций. Первая неудачная установка не имеет предыдущего образа.

Работающий компьютер и Docker Desktop необходимы для локального CD. Окружения не будут доступны при выключенном компьютере. Существующий запуск приложения на 8080 остаётся отдельным от этих окружений.
