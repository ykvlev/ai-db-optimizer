# Протокол следующего сравнения моделей

Статус: подготовка. Этот документ фиксирует правила до нового сбора ответов;
сам корпус ещё не зафиксирован. Он не содержит новых результатов.

## Вопрос опыта

На каких допустимых состояниях обнаруживаются изменения результатов после
переписывания SQL двумя разными моделями? Дополнительно проверяется перенос
исходных запросов и ручных контрольных пар между MySQL и PostgreSQL.
Результаты проверки инфраструктуры не заменяют ответы моделей.

## Корпус и разделение

До генерации ответов сохранить исходные SQL, полный DDL, состояния баз,
эталонные результаты, положительные контроли, правила сравнения и SHA256
каждого файла. Эталонные SQL выполнить на обеих СУБД. Затем зафиксировать
коммит и успешный CI. После этого не менять запросы или состояния по увиденным
ответам. Исправление корпуса создаёт новую версию и требует отдельного анализа.

Целевой объём первого этапа — 12 новых шаблонов в одном дополнительном домене.
Если запросы составлены вручную, обозначать их как синтетический дополнительный
корпус, а не как независимую выборку рабочих SQL. До заявлений о переносимости
нужен отдельный внешний корпус с проверенными происхождением и лицензией.

Включить пустые таблицы, группы с нулевыми агрегатами, повторы после соединений,
NULL только в допускающих их столбцах, включающие границы и равные ключи
сортировки. Для ORDER BY без полного разрешения равенств не сравнивать
произвольный порядок внутри равных ключей. Неоднозначный LIMIT исключать
заранее или описывать допустимое множество ответов.

## Модели и стоимость

Кандидаты: Qwen2.5-Coder 7B и Phi-3.5 Mini 3.8B. Вторую модель включать только
после успешной проверки доступности. Они различаются размером и специализацией;
не приписывать разницу результатов только семейству модели.

Одинаковые для обеих моделей: исходные SQL, DDL, текст задания, температура 0,
контекст 4096 токенов, предел ответа 1200 токенов, один ответ на запрос.
Сохранить полный digest модели, квантование, версию Ollama, параметры и
неизменённый ответ. Проверить, что весь ввод помещается в контекст без усечения.

Запускать последовательно, выгружать модель после серии. Начать с одного
служебного запроса вне корпуса; он проверяет доступность, не качество SQL.
На запрос отводить не более 240 секунд. После двух последовательных сервисных
ошибок остановить эту модель, сохранить ошибки и перейти к анализу доступного.
Не повторять неудачный SQL-запрос автоматически и не выбирать лучший ответ.

Для основного этапа запланировано 24 запроса генерации (12 × 2 модели).
До запуска сверить оставшийся ранее установленный бюджет; служебные пробы
записывать отдельно и также учитывать в общем числе обращений.

## Проверка результатов

Исполнять только проверенные SELECT в изолированной схеме, с ограничением
времени и без доступа на запись. Не выполнять неизвестные функции или ссылки
на другие схемы. Отдельно учитывать ошибки сервиса, разбора ответа,
неподдерживаемый SQL, отказ от переписывания, ошибку исполнения,
контрпример и отсутствие найденного контрпримера.

Сравнивать мультимножества строк; порядок — только когда он определён запросом.
Типы и имена столбцов записывать отдельно от равенства значений. Совпадение
описания столбцов одного драйвера не означает одинаковый интерфейс разных СУБД.

Для каждого найденного расхождения сохранить допустимое состояние и повторно
исполнить пару на новой схеме. Не считать каждый такой повтор новым запросом
или независимым наблюдением. Случайные методы сравнивать при одинаковом числе
состояний; описывать пересечение подмножеств и ошибки, известные только на
исследованном наборе. Конечное совпадение не называть доказанной эквивалентностью.

## Выпуск

Изменения инфраструктуры проходят push → build → test → package → registry,
затем staging → production на локальном исполнителе. Успех CI не подтверждает
CD. Регистрация исполнителя остаётся отдельным незавершённым условием.

Новый отчёт хранить отдельно от ранее поданной рукописи. Обновление статьи
выполнять только после проверки новых фактических результатов и отдельной
подготовки согласованного комплекта.
