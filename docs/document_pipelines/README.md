# Конвейеры научных документов

Скрипты, которыми собраны научные документы проекта. До 16 октября 2026 года они
лежали вне версионного контроля: конвейер рукописи — в неотслеживаемой папке `tmp/`,
а построитель приложения к НИР — вообще вне репозитория. Теперь они собраны здесь,
чтобы их можно было проверить, передать и восстановить.

## Что здесь лежит

| Папка | Что собирает |
|---|---|
| `sitito/` | Рукопись для конференции МГУ и журнала СИТИТО: `manuscript.md` (текст) + `build.py` (сборка DOCX из официального шаблона) + `export.ps1` (DOC и PDF через Word) |
| `nir_appendix/` | Приложение А к конкурсной НИР «Наука 3.5»: `build_appendix.py` дописывает приложение с тремя таблицами в согласованную НИР, не меняя основную часть |

Проверочные скрипты в этих же папках (`verify_tables.py`, `overlap.py`) не собирают
документы, а сверяют числа в них с исходными данными и измеряют пересечение
рукописей. Они запускаются повторно после любых правок.

## Как запускать

```
pip install -r docs/document_pipelines/requirements-docs.txt

python docs/document_pipelines/sitito/build.py          # DOCX рукописи
pwsh   docs/document_pipelines/sitito/export.ps1        # DOC и PDF через Word
python docs/document_pipelines/sitito/verify_tables.py  # сверка чисел с данными

python docs/document_pipelines/nir_appendix/build_appendix.py
python docs/document_pipelines/nir_appendix/verify_tables.py
```

## Важные оговорки

**Пути привязаны к рабочему месту.** Скрипты содержат абсолютные пути вида
`C:\Users\<пользователь>\Documents\Science\...`, потому что собирают документы из
конкретной рабочей папки, а не из репозитория. Для запуска на другой машине эти
константы нужно заменить. Параметризация путей не делалась, чтобы не менять
поведение уже проверенных сборок.

**Шаблон издателя не входит в репозиторий.** `sitito/build.py` собирает рукопись из
файла `sitito_template.docx`, который распространяет редакция. Файл не публикуется
здесь по понятным причинам; без него сборка не запустится.

**Экспорт PDF идёт через Microsoft Word**, а не через LibreOffice: LibreOffice теряет
номера страниц в оглавлении, собранном полями `PAGEREF`. Поэтому `export.ps1`
обращается к Word через COM.

**Длинный кириллический путь.** Word не открывает документ, если полный путь длинный
(у нас — 191 символ с кириллицей и тире): процесс уходит в ожидание, хотя файл
исправен и LibreOffice его открывает. Поэтому экспорт делается так: документ
копируется в короткий путь, там обновляются поля и выполняется экспорт, затем DOCX
и PDF возвращаются на место. Это уже случалось и стоило времени на диагностику.

**Зависимости.** `requirements-docs.txt` — отдельный список: `pymupdf` для разбора
PDF и `Pillow` для контактных листов. В `backend/requirements.txt` они не добавлены
намеренно: приложению они не нужны.

**Это не CI/CD.** Конвейер документов по-прежнему запускается вручную. Правило
проекта требует проводить изменения через CI/CD; для документов он не настроен, и
эти скрипты — первый шаг к тому, чтобы это стало возможно.
