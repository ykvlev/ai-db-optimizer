# Эксперимент «ИИ против человека» (пункт 12 плана)

Сравнение ручной оптимизации SQL-запросов с языковыми моделями на тех же задачах и с той же проверкой.

## Материалы

| Файл | Назначение |
|---|---|
| `Задания_для_участников.docx` | раздаточный материал: правила, схема базы, 10 заданий (собирается `node build_study.js`) |
| `tasks.json` | задания: ключ запроса из набора shop-bench-v1 и исходный SQL |
| `schema.json` | схема демо-базы MySQL с индексами |
| `answers_template.csv` | шаблон для ввода ответов (participant, experience, task, sql) |
| `evaluate_humans.py` | проверка ответов: совпадение результата и бенчмарк, сравнение с моделями |

Задания подобраны так, чтобы охватить разные ситуации: простые случаи (функция над датой), случаи, где модели
ошибались (пагинация OFFSET, подзапросы в SELECT, отчёт с соединениями), и контрольный уже оптимальный запрос.

## Порядок проведения

1. Участники — 5–10 студентов с опытом SQL. Участие добровольное и анонимное: каждому выдаётся код (P01, P02, …).
2. Время — 45 минут, без инструментов ИИ, документацией MySQL пользоваться можно.
3. Ответы переносятся в `answers.csv` по шаблону; пустое поле `sql` означает «без изменений».
4. Запуск проверки (сервер программы и демо-база MySQL должны быть запущены):

```
backend\.venv\Scripts\python docs\human_study\evaluate_humans.py docs\human_study\answers.csv
```

Результат: `results_humans.csv` (исход и ускорение по каждому ответу) и `summary.json` — сводка по участникам
и моделям эксперимента 7 на тех же 10 задачах.

## Что сравнивается

Число улучшенных запросов, число ответов, изменивших результат, замедления, а также время на решение
(у моделей — время ответа, у людей — 45 минут на всё). Для статьи (пункт 13 плана) полезно отдельно разобрать,
какие ошибки делают люди и совпадают ли они с ошибками моделей.
