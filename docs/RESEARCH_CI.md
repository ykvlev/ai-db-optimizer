# Проверки исследовательского стенда в CI

Существующий конвейер выполняет push → build → test → package → registry.
На этапе test `backend/tests/test_research_controls.py` исполняет 14 проверок:
по четыре положительные пары, два отрицательных контроля значений и один
отрицательный контроль типов на MySQL и PostgreSQL.

Проверки используют небольшие синтетические данные во временных таблицах
с отдельным соединением на каждый тест. Закрытие соединения удаляет только
его временные таблицы. Таблицы приложения и сохранённые исследовательские
состояния не изменяются. Недоступность СУБД и пропуск контролей останавливают CI.
Полные результаты входят в артефакт `test-results`.

Это проверка условий сравнения SQL, а не эксперимент с языковыми моделями.
Она не воспроизводит результаты статьи и не увеличивает её выборку. Рукописи,
сырые ответы моделей и непубличные материалы не нужны для этого конвейера.

После успешного test существующий конвейер собирает образ приложения и
публикует его в registry. Staging и production выполняются отдельно через
`CD local`, после успешного CI основной ветки, на зарегистрированном локальном
исполнителе `science-deploy`; production требует подтверждения окружения.
Пока исполнитель отсутствует, CD не завершён. См. `CI_CD.md`.

Следующий самостоятельный этап — фиксированный протокол нового корпуса,
сбор настоящих ответов доступной второй модели и отдельные артефакты опытов.
Данные этих опытов нельзя подменять результатами настоящих контрольных тестов.
